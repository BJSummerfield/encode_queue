## Findings

1. **[major]** TST-03 (docs/CONVENTIONS.md:734-753; same defect in GEN-01's secondary
   grep, L755+) — the How-to-check `grep -rnE "\.unwrap\(\)|\.expect\(" src |
   grep -v "#[cfg(test)]"` / `grep -rnE "\.unwrap\(\)|\.expect\(|panic!|unreachable!"
   src/ | grep -v "cfg(test)"` is line-based and **can never pass on compliant code**:
   the `#[cfg(test)]` attribute sits on the `mod tests {` line, not on the `unwrap()`
   line. Verified with a scratch file mirroring the doc's own TST-01/TST-03 target code
   (a `#[cfg(test)] mod tests` containing a legitimate fixture `unwrap()`):
   `grep -rnE "\.unwrap\(\)|\.expect\(|panic!|unreachable!" src/ | grep -v "cfg(test)"`
   still printed `src/domain/queue.rs:11: let e = QueueEntry::new("nix build").unwrap();`
   — a false positive on exactly the code TST-03 *permits*. A binding check that flags
   compliant test code will force engineers into `#[allow]` (GEN-04 violation) or make
   the doc look wrong. Fix: drop the line-based grep from both check lines; the
   module-scoped clippy deny in GEN-01 (verified working) is the correct and sufficient
   mechanism, optionally supplemented by a scope-aware check (e.g. `cargo clippy
   --all-targets` alone, or a script that tracks `#[cfg(test)]` module scope).
2. **[major]** TY-02 (docs/CONVENTIONS.md:367-395) — the How-to-check
   `grep -rnE "fn [a-z_0-9]+\((self, )*(&str|String|&Path|PathBuf)" src/domain src/ports`
   only matches when a raw type is the *first unnamed* parameter; it misses named
   parameters, which are the common (and target-layout-relevant) case. Verified: against
   `fn append(&self, entry: &str) -> Result<(), io::Error>;` and
   `fn run(&self, entry: &str) -> …` (exactly the "port API takes raw `&str`" violation
   TY-02 forbids) the documented regex exits 1 (no match); the current repo's
   `fn open_editor(file_path: &str)` (src/main.rs:105) would also have missed. The check
   cannot detect the violation it is meant to catch. Fix (verified working on the same
   fixtures, caught all violations including `pub fn new(s: &str)`): `grep -rnE
   "fn [a-z_0-9]+ *\([^)]*: *(&str|String|&Path|PathBuf)\b" src/domain src/ports` (note
   the line-based limitation for multi-line signatures), or make this a manual check of
   port signatures with that grep as a spot check.
3. **[minor]** ARCH-01 (L45+), ARCH-03 (L117+), TY-02, TY-03 (L397+), TST-01 (L671+):
   their greps target `src/domain`, `src/ports`, `src/domain/queue`, which do not exist
   yet, so in the current tree they exit 2 with `grep: src/domain: No such file or
   directory` instead of a clean "→ empty" (verified). The doc's framing (repo is a
   single-file CLI today; Target layout describes the end state) makes intent clear and

   (`test -d src/domain && grep … || true`).
4. **[minor]** TY-05 (L459+) — "clippy lint `inherent_to_string_shadow_display` stays
