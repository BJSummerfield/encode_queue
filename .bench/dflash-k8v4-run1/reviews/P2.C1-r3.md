   ERR-04's good example uses `map_err(RunError::Wait)` for the same failure
   (`docs/CONVENTIONS.md:262`), and ERR-04's rule names `RunError::Other(std::io::Error)`.
   Two snippets in one doc name the same port error's variants differently (`Waited` vs `Wait`),
   which can mislead the worker building the enum.
   Fix: use one name in both snippets (e.g. `RunError::Waited { code: i32 }` in ERR-04's example,
   with `map_err(|code| RunError::Waited { code })` for the wait failure).

   `pub trait QueueStore: Clone + 'static { … }` (`docs/CONVENTIONS.md:639`). A reader following
   the example keeps a supertrait stack the rule forbids.
   Fix: make the good example a bare `pub trait QueueStore {` (matching ARCH-01/TST-01's mock-based
   design, where no supertraits are needed for a single-threaded CLI).
