## Findings

1. **[major] Raw-primitive service signature — `QueueService::remove_entry(&self, pos: u64)` (src/domain/queue/service.rs:244).** A `pub` domain (business-logic) function takes a raw `u64` — precisely the "u32-style primitive" class that check 3 / ARCH-04 forbid outside the accepted-exception list (accessors + clap boundary). The `QueueEntryIndex` newtype exists and its own doc (queue/mod.rs:70-71) claims it is "parsed at the `rm` boundary (TY-01) so the service never sees a raw index" — contradicted by cli.rs:158, which unwraps it (`index.as_u32() as u64`) before crossing the boundary, forcing the service to re-validate (`pos == 0 || pos > entries.len() as u64`, service.rs:246) and letting raw `u64` leak into `QueueError::NoEntry(u64)` (service.rs:84) and `QueueEntryError::IndexOutOfRange { requested: u64 }` (queue/mod.rs:172). Fix: `pub fn remove_entry(&self, pos: QueueEntryIndex) -> Result<(), QueueError>` (keep the range check; `NoEntry`/`IndexOutOfRange` payloads become the newtype or its `as_u32`); cli.rs passes the newtype through un-unwrapped.

2. **[major] Dead exported dispatch macro + duplicate production macro — `impl_dispatch!` (src/ports/dispatch.rs:29, `#[macro_export]`).** Its only call site is a test-local `ShellRunner{Alpha, Beta}` enum inside the macro's own `#[cfg(test)]` module (dispatch.rs:79); zero production uses → unreachable `pub` API (check 5), while the production `ShellRunner` (outbound/shell.rs) gets its `impl CommandRunner` from a second, parallel macro `delegate_run!` (shell.rs:70-83) that re-implements the same DISP-02 pattern. This fails DISP-02's How-to-check ("every multi-implementation enum has exactly one `impl <Port> for <Enum>` and it comes from an `impl_dispatch!` call") and duplicates dispatch logic in two macros. Fix: route the production `ShellRunner` impl through `impl_dispatch!` (generalising the expansion to the `Shell::program()` indirection, or holding the program per variant) and delete `delegate_run!` — or, if the shell-runner shape is the intended permanent form, move/generalise the canonical macro so one macro owns all dispatch.

3. **[major] Composition root does file I/O — `fn main` (src/main.rs:29-86, 58 lines) calls `fs::create_dir_all(queue_dir)` (main.rs:49, `use std::fs` at line 18).** ARCH-02: "`main()` does exactly: read config from env, construct the concrete outbound adapters, wire them into the service, call the inbound CLI adapter's `run`, and map the top-level error … No loops, no file I/O, no command parsing, no process spawning," with How-to-check "`fn main` is under ~40 lines and contains no `fs::`, no `Command::new`, no read_line" — both counts fail. The code's own comment (main.rs:44-48, "Legacy bootstrap parity") admits it is a workaround for the behaviour contract's "dir created if missing" requirement; the structural home is outbound — `FileQueueStore`/`FileQueueLock` constructors (or an `ensure_dir` on the store port), since `append`/`drop_first`/`write_all`/`append_failure` (queue_file.rs, `OpenOptions::create(true)` without parent creation) and `acquire` (lock.rs `File::create_new`) all require the parent directory to exist. Fix: move directory creation into the outbound adapters and let `main` stay bootstrap-only.

4. **[major] README does not describe the current (P5/P6) behaviour.** All sub-items verified against code and the release binary (see Check 6): (a) "Fish shell" stated as the (implied-only) execution shell — wrong since `ENCODE_QUEUE_SHELL` (fish|bash|sh, default fish); (b) `rm <N>` undocumented; (c) `ls -n/--numbered` undocumented; (d) `start --stop-on-error` and the `failed.txt` failure log (`<unix_ts>\t<exit_code>\t<command>\n`) undocumented; (e) `queue.lock` single-runner lock and exit 3 undocumented; (f) `ENCODE_QUEUE_DIR` directory override undocumented (README's Configuration section names only `~/.config/encode_queue/commands.txt` and `EDITOR`; no file-vs-dir misstatement present); (g) no exit-code contract (0/1/2/3) at all. Rated [major] per the brief's Check 6 rubric; sub-items (a)-(g) are the precise input list for P8.D1's rewrite.

5. **[minor] Stale module doc — `src/outbound/mod.rs:1`:** "Outbound adapters (domain newtypes → external I/O: files, `fish`, editor)" names `fish` specifically (the process boundary is now the shell-agnostic `ShellRunner`, P6.F2) and omits the fourth adapter (`lock`). 6. **[minor] Missing unit test: whitespace-only `ENCODE_QUEUE_SHELL`.** `config.rs` tests cover `None` and `""` (`from_vars_shell_unset_or_empty_defaults_to_fish`) but not `"   "`; behaviour is correct (config.rs:113-116; verified rc 0 on the binary). 7. **[minor] `ShellError` error-type shape (src/domain/shell.rs:21-25).** A `#[derive(thiserror::Error)]` *struct* with `pub input: String`, rather than the named-variant error-enum pattern ERR-02/ERR-04 prescribe ("error enum", "every expected failure is a named variant"), and with a `pub` field (OP5/TY-03: domain types expose constructors and accessors, never `pub` fields). 10. **[minor] `QueueService::start(&self, stop_on_error: bool)` (service.rs:137) takes a raw `bool` mode flag.** Not in the "u32-style data primitive" class (no newtype convention exists for mode flags in CONVENTIONS.md), so this is an observation, not a check-3 violation — noted for completeness so the P8 author can decide whether a `StopOnError`-style flag newtype is warranted.
