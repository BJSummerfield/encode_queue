**Deviation 1 — D2 → D2′ (supervisor-adjudicated, decisions.md 22:05): CONFORMANT.**
Verified the implementation matches D2′ exactly:
- Port: `QueueStore::write_all(&self, entries: &[QueueEntry]) -> Result<(), QueueStoreError>` added (`src/ports/queue_store.rs`), doc "Replace the entire queue with `entries` (truncate + rewrite)" ✓.
- Outbound: `FileQueueStore::write_all` (`src/outbound/queue_file.rs`) uses the identical pattern to `drop_first` — same `OpenOptions::new().write(true).truncate(true).open(self.path.as_path())`, same `map_io_error(self.path.as_path(), err)` on the open error, same per-entry `writeln!(file, "{}", entry).map_err(QueueStoreError::Io)?` — and, unlike `drop_first` (which early-returns on an empty queue), the truncate+rewrite runs **unconditionally** so an empty slice leaves an empty file; the difference is documented in the method doc ✓ (verified by side-by-side read of both impls).
- Service: `remove_entry(pos: u64)` = exactly one `read_all` + filter of 0-based index `pos - 1` + one `write_all`; `pos == 0 || pos > len` → `QueueError::NoEntry(pos)` with the queue untouched; missing file surfaces `QueueError::Store(QueueFileMissing)` before any rewrite (deliberately not softened like `ls`) ✓. The doc comment documents the one-read/one-write trade-off AND the empty-slice rewrite ✓.
- `QueueError` gains ONLY `NoEntry(u64)` with `#[error("no queue entry at position {0}")]`; the four existing arms (`Store`/`Run`/`Editor`/`Invalid`) are byte-unchanged in the diff ✓.
